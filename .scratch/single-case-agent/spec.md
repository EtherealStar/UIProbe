# UIProbe 单条用例 Agent 设计

一次运行接收一条测试用例，执行 Agent 依据业务步骤和逐帧截图规划动作。程序驱动浏览器，验证器按用例原始预期给出结论。本地记录应能回答三个问题：模型当时看到什么、程序做了什么、哪条证据决定了测试结果。

## 输入

保留现有 JSON 格式。下面这份输入对应一次运行。

```json
[
  {
    "title": "正确账号和密码登录成功",
    "priority": "P0",
    "case_type": "functional",
    "is_smoke": true,
    "precondition": "已有正常状态的测试账号",
    "steps": ["打开登录页面", "输入正确的账号和密码", "点击登录按钮"],
    "expected_result": "登录成功，跳转到首页"
  }
]
```

程序另行传入入口 URL、可引用的测试数据、模型配置、步数和时间预算，以及验收配置。上例中，执行 Agent 能看到可用的账号和密码引用名，执行器持有实际值。优先级、用例类型和冒烟标记进入运行元数据。

## 模块接口

各模块的调用约定、错误语义和接口验证场景见[模块设计索引](../../docs/design/modules/README.md)。

下列动作名、字段名及文件布局是实现草案。业务行为和取舍见[设计决策图](map.md)。

| 模块 | 接收 | 产生或负责 |
|---|---|---|
| 用例解析 | JSON 数组、运行配置 | 用 Pydantic 读取一条记录，保留原始预期。把标题、前置条件和有序业务步骤提供给执行 Agent 形成目标。建议首版入口对零条或多条返回输入错误。 |
| 模型服务与连接 | 执行上下文，或视觉验收请求 | Pydantic AI 定义两种角色，底层通过 OpenAI SDK 调用配置的模型。执行 Agent 需要图像输入和工具调用能力；独立视觉验证 Agent 接收预期和证据图，输出判断与依据。 |
| 执行循环 | 执行目标、截图消息历史、步数和时间预算 | 管理运行状态。每轮取得一个动作请求，反馈工具结果和最新截图，或进入验收。由循环决定是否开始下一轮。 |
| 动作约束 | 工具名、参数、当前截图和数据引用表 | 从 Pydantic 动作类型生成 JSON Schema；执行前校验类型、范围及运行状态。拒绝动作时返回可反馈给模型的具体错误。 |
| 浏览器控制 | 已校验动作、Playwright 页面 | 管理一个浏览器会话，打开入口、按坐标点击、向焦点控件输入和截取视口 PNG。返回动作结果、截图及其尺寸。 |
| 结果验证 | 原始预期、验收截图、配置的 DOM 条件、当前页面 | 运行所选断言，分别记录状态和证据，再聚合运行结论。 |
| 执行记录 | 运行、模型决策、浏览器动作和断言事件 | 本地写 JSONL、PNG 和最终 JSON。通过 OpenTelemetry 的 OTLP/HTTP 向 Langfuse 上报 trace。 |

## 一轮执行

1. 程序建立运行 ID 和整次运行的截止时间，打开入口页，保存初始视口截图。每张截图带编号、发送图片的宽高和视口的 CSS 宽高。
2. 将目标、可用数据引用名、动作定义及截图历史交给执行 Agent。每轮计一步，至多派发一个动作。建议使用 Pydantic AI 的结构化工具输出将决策交回外层循环，保留程序对派发和计步的控制。
3. 程序校验请求。坐标动作用最新截图编号，原点为图片左上角，范围为 `0 ≤ x < 图宽`、`0 ≤ y < 图高`。沿用完整视口截图、无裁剪和留边时，横坐标换算为 `x × 视口 CSS 宽 / 发送图宽`，纵坐标同理。使用 CSS 比例截图且原尺寸发送时，两组坐标数值相同。
4. 动作执行后截取新图，将结果和图像追加到消息历史。参数错误或旧图引用同样消耗本轮步数，返回错误并保留当前图。等待动作结束后重新截图。浏览器或模型调用受剩余时间限制。
5. 收到验收请求后停止页面操作并执行断言。若最后一个允许的步骤请求了验收，在剩余时间内完成验收。步数耗尽或整次运行超时而无结论时，记为 `error`，写明停止原因和最近可用的截图。

### 登录用例的最小动作集合（建议）

| 工具请求 | 约定 |
|---|---|
| `click(frame_id, x, y)` | 校验图片编号和像素坐标，换算后执行点击。 |
| `type_value(ref)` | 从运行配置解析已知的数据引用，向当前焦点控件输入。动作记录只保留引用名。 |
| `wait(duration_ms)` | 等待指定时间并取得新图。校验时长为正且处于配置的等待上限内。 |
| `verify()` | 请求验收当前页面，结果由验证器产生。 |

## 验收与停止

用例可配置视觉、DOM 或组合验收，至少启用一种。视觉验收读取原始 `expected_result` 与验收截图，记录图像编号和可见依据。DOM 验收由程序提供定位器及条件，记录预期和实际观察。验证器独立取证，执行 Agent 的完成声明仅用于触发验收。

| 状态 | 登录示例 |
|---|---|
| `passed` | 所有必选断言通过。例如截图呈现首页，用户菜单也出现预期昵称。 |
| `failed` | 必选断言有明确反例。例如页面明确显示“账号已停用”，与登录成功的预期矛盾。 |
| `error` | 无法得出业务结论。例如超时、执行预算耗尽，或一项必选检查因服务故障无结论且其余项均通过。 |

建议组合验收逐项留存结果。若同次运行已有明确的必选断言失败，另一个检查又发生故障，建议总状态取 `failed`，并在故障检查项保留 `error`。

## 本地记录与 Langfuse

每次运行使用独立目录。建议以 `run_id` 关联本地文件和 Langfuse 的根 span，以 `step`、`frame_id` 和断言标识关联具体证据。

| 产物 | 内容 |
|---|---|
| `events.jsonl` | 按时间追加运行及决策事件。每轮保存输入图、动作、参数、换算坐标、耗时、动作结果或校验错误、输出图。 |
| `screenshots/<frame_id>.png` | 保存初始图及浏览器动作后的图。被校验拒绝的动作可引用已有图。 |
| `result.json` | 保存运行 ID、用例与执行目标、原始预期、最终状态、停止原因、最后截图和每项断言的证据。 |
| Langfuse trace | 一次运行一条 trace，包含模型决策、浏览器动作和断言的子 span。只上报关联编号、耗时、动作摘要和断言结论。PNG 留在本地，关闭含完整消息内容的自动上报，以免截图随模型输入导出。上报失败时保留本地结果。 |

## 登录用例走查

以下为设计示例。程序打开登录页取得 `f0`；执行 Agent 看图点击账号框，用 `type_value("test_username")` 请求输入，再对密码框执行对应操作。四次动作后，`f4` 显示可以提交的表单。

假设视口为 1280 × 720，发送图片为 640 × 360。第 5 步模型从 `f4` 返回点击点 (320, 210)，程序在视口位置 (640, 420) 点击。事件将两组坐标与 `f4`、新截图 `f5` 关联。若 `f5` 显示加载中，下一步可等待并得到 `f6`。若 `f6` 显示首页，则请求验收；若显示登录错误，同样可以请求验收。

在组合验收示例中，视觉验证器依据原始预期检查 `f6`，DOM 验证器检查站点配置的用户菜单。两项均满足时，最终 JSON 记录 `passed` 和两份依据。开发者从结论可以找到验收截图，再沿步骤编号回看提交位置与动作前后的页面变化。
