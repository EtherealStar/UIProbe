# 02: 新格式单检查点显式提交并返回批次结果

**What to build:** 调用方用新 Case 和配置结构运行一条单检查点测试，执行模型通过固定提交工具交付初图或最新已保存图，再以正常文本结束；独立视觉判断与执行结束分别保存，统一返回包含该条运行的 SuiteResult。

**Blocked by:** 01 隔离现有验收材料与追踪归属.

**Status:** completed

- [x] 单 Case 使用稳定 id、name 和非空 checkpoints，配置使用默认值与覆盖容器；拒绝旧顶层用例结构，单对象也进入批次生命周期。
- [x] 输入准备早于 Browser 和模型请求，合法运行形成 PreparedCase；非法输入属于批次或输入条目，不创建非法 Session。
- [x] 零动作无需 TODO 即可提交初图，提交不扣动作、不重拍；成功回执之前已保存证据和提交事实并登记唯一验收。
- [x] 执行模型初始只取得当前阶段和引用名，工具仅获得提交能力；正常最终文本形成 ExecutionOutcome，不再被当成证据提交。
- [x] 最后检查点提交后禁用全部工具；提前最终文本保留未提交状态并形成 error，不补交或猜测结论。
- [x] 合法 passed、failed、证据不足 error 与系统故障按共享契约合成；执行退出后开始关闭 Browser，冻结材料验收不再依赖页面，返回前完成收敛。
- [x] 共享资源由 Suite 创建并关闭，根追踪与批次结果在收尾后保存；批次和会话记录独占并列目录，调用方取得结果后不再回写最后 Case。
- [x] CLI 保留原有选项及 0／1／2 退出码，stdout 为 SuiteResult；最小样例和受影响既有回归随切片迁移，真实本地页面与受控原生模型验证完整路径。

验证见 [新格式单检查点与串行批次实施证据](../../../docs/exec-plans/serial-async-agent/progress.md#2026-11-20-新格式单检查点与串行批次实施证据)。
