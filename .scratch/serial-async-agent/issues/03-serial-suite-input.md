# 03: 整批预检后串行运行并隔离 Case 配置

**What to build:** 调用方提交多个 Case 后，系统先完整检查输入与覆盖配置，保留每个可定位条目，再按原顺序运行合法 Case。非法项及普通失败不阻止其他合法项，各 Case 的页面、历史、数据和预算互不污染。

**Blocked by:** 02 新格式单检查点显式提交并返回批次结果.

**Status:** completed

- [x] 单对象和仅含非空 cases 的批次对象通过同一准备入口；整份校验及有效配置合并在任何 Browser 或模型请求前完成。
- [x] SourceRef 独立于 Case ID 定位条目；重复 Case ID 的全部冲突项非法，检查点和断言的唯一性分别限制在所属作用域。
- [x] 公共解析／外层／默认值／覆盖容器错误和未匹配覆盖 ID 阻止整批；仍保留可确定的条目输入错误，其余合法结构项为 not_run。
- [x] 单条非法 Case 或已匹配覆盖的值／字段非法只影响本条；拒绝未知字段、null 删除和非严格预算值，错误不回显实际引用值或未知字段原文。
- [x] 入口覆盖整值替换，引用值按名合并，空映射继承；合并不修改共享默认值，真实页面证明不同 Case 使用自己的入口和值。
- [x] 按输入位置保存合法、非法及未运行条目；上一 Session 的执行、验收、Browser 清理和最终记录全部收敛后才启动下一条。
- [x] Case passed、failed 或普通 error 后继续；不重跑。每条运行独占 Browser、Context、预算和记录，共享客户端跨 Case 复用并只在批次收尾关闭。
- [x] 真实本地页面和受控模型通过混合输入、顺序与状态隔离回归；批次只有一份完整 trace，子作用域不会被后续 Case 覆盖。

验证见 [新格式单检查点与串行批次实施证据](../../../docs/exec-plans/serial-async-agent/progress.md#2026-11-20-新格式单检查点与串行批次实施证据)。
