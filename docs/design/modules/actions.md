# 工具调用

工具调用 module 使用 Pydantic AI 的工具机制，集中实现 UIProbe 的公共执行规则。框架负责函数注册、参数解析与类型校验、工具调用和结果配对。项目负责计划门槛、会话预算、页面操作后的截图、记录和工具可用性，不创建 ToolSpec 注册表或手写模型—工具分发循环。

## 装配和内部职责

应用将 click、fill_value、scroll、wait、replace_todo 注册到 FunctionToolset。工具通过 RunContext.deps 取得本次运行的 Context、Browser、RunBudget 和记录对象；模型只填写业务参数。工具具体含义分别是点击、覆盖填写、页面垂直滚动、有界等待和计划整表替换。

外围执行层通过 WrapperToolset 包装既有工具执行。返回值使用项目明确的数据对象；需要运行时输出校验时显式构造 Pydantic 对象，不把返回类型注解当作校验器。框架 ToolReturn 可区分结构化结果、模型内容和内部元数据；完整消息仍使用框架原生类型。

| 标记 | 浏览器工具 | TODO 工具 | 用途 |
|---|---|---|---|
| sequential | true | false | 框架串行屏障，防止浏览器操作及截图与其他工具重叠 |
| metadata.refresh_browser_state | true | false | 项目识别占动作额度、操作后取图和更新观察的路径 |

metadata 不是模型参数。TODO 可与其他非串行工具并发，但必须遵守浏览器工具的屏障。同一模型响应可以包含多次调用，不统一拒绝多工具响应。

## 浏览器动作路径

1. 检查共享截止时间、剩余额度及 Context.plan_created；计划必须曾通过非空初始列表创建。
2. 完成参数和业务状态的无副作用校验。各工具报告自己的错误；Browser 负责旧图、坐标、引用和焦点等规则。外围层不重复这些规则。
3. 所有校验通过后，在实际操作派发前调用 RunBudget.claim_browser_action，取得动作序号。Browser 的预检与派发需要接在此执行路径内，不能校验未完就先扣额度。
4. 执行一次页面操作，在同一串行区域调用 Browser.capture。具体工具本身不另行截图。
5. 保存新图片，再写引用它的事件；成功取得的观察通过 Context 的统一入口更新。构造动作摘要和截图编号关联，交回框架。Context 在下一次请求末尾统一附加最新图片。

初始化由 Session 完成，不计 Agent 动作。派发前校验拒绝不计数；已派发即计数，后续故障不退还。操作后的截图或本地记录失败立即停止执行，保留最近可用证据，不重放动作。

只有这条路径能在初始化后更新 Context.browser_state。实际操作、截图和观察更新不能脱离串行区域成为后台任务。

## 额度耗尽

最后一次允许的操作及其截图完成后，所有工具均被禁用，包括 replace_todo。下一次模型请求提示动作额度已耗尽，要求根据当前观察总结并提交。原有框架循环继续承担模型交互，不建立独立总结阶段。

禁用同时包括不再向模型开放工具，以及执行时拒绝模型仍然提出的调用。同一响应中尚未执行的工具也需要检查额度耗尽后的禁用状态，不能继续执行 TODO。拒绝反馈不派发页面操作；剩余模型请求额度、工具调用额度、纠正重试配置和 deadline_at 防止反复调用。预算或时间用尽而未提交时返回执行错误。

## 工具纠正与致命故障

每个工具按自身错误反馈具体原因，由 LLM 决定修正；公共层仅反馈计划、额度、截止时间等共同限制。可纠正的派发前问题使用框架 ModelRetry 等纠正机制，不当作成功结果。所有工具共用 Agent 的纠正重试配置，不增加项目重试计数器，也不代替模型修改参数。

例如同一响应两次 click 引用同一截图：第一次操作更新观察后，第二次由 Browser 拒绝旧图；若第一次已耗尽动作额度，则第二次先按工具禁用规则拒绝。

连接故障、操作派发后故障、不支持的新页面、截图失败与本地记录失败向上传给 Session，不能转成可重放的参数纠正。错误、摘要及遥测不回显实际输入值。
